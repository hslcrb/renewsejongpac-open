01 / 첨부 관찰 · 공식 설명

보와 기둥, 천·지·인

첨부 로고는 굵은 가로획 아래 여섯 음절과 원형·직선이 반복됩니다. 공식 CI는 건축물의 보와 여섯 기둥을 로고 구조로 확장합니다.[1] 검정이 주조색이며, 하늘·황토·노랑은 각각 천·지·인을 나타냅니다.[2]

02 / 디자인 해석

단단한 틀, 열린 무대

로고의 검정과 반복 구조는 단단한 인상을, 세 가지 유채색은 다양성을 표현하는 장치로 읽힙니다. 따라서 화면 전체를 여러 색으로 채우기보다, 콘텐츠가 돋보이는 정돈된 틀을 만드는 방향이 적합하다고 판단했습니다.

03 / 웹 적용 제안

로고는 보존, 정보는 정돈

공식 로고를 일반 글꼴로 다시 만들지 않습니다. 메뉴·본문에는 Pretendard를 적용하고, 검정은 핵심 행동에 고정합니다. 새 유채색 대신 중립색 3개만 보완해 배경·설명·구분선을 구별합니다.

기존 컬러의 값은 어떻게 정했나요?

첨부 자료와 공식 CI의 RGB 값을 그대로 HEX로 변환했습니다. 하늘색 84·200·232 → #54C8E8, 노랑 255·232·0 → #FFE800, 황토 195·109·21 → #C36D15입니다. 캡처 이미지의 픽셀색을 추출하거나 Pantone을 임의 변환하지 않았습니다. 자료의 흰색에 하늘색과 같은 “PANTONE 305 C”가 기재되어 있으므로 이 표기는 사용하지 않고, 흰색 RGB 255·255·255 → #FFFFFF를 기준으로 삼았습니다.[2]

Figma 등록 순서[4]

1. 원본값 등록Variables에서 01. Primitives Collection을 만듭니다. Color 타입으로 변수 8개와 HEX 값을 입력합니다.

2. 역할 연결02. Semantic에 Color 변수를 만듭니다. 값에서 Create alias를 선택하고 표에 적힌 Primitive를 검색해 연결합니다.

3. 화면에 적용버튼·카드·텍스트에는 Semantic을 적용합니다. 예: 버튼 배경은 action/primary, 버튼 글자는 text/inverse.

두 Collection 모두 모드는 light 하나로 시작합니다. 이 HTML은 수동 등록용 명세이며 Figma에 자동 등록하지 않습니다. 복사 버튼은 문자열을 복사할 뿐, Alias 연결 자체를 생성하지 않습니다.

유채색 위 작은 흰색 글자는 피하기흰색 / 하늘은 1.94:1, 흰색 / 노랑은 1.25:1, 흰색 / 황토는 3.81:1로 일반 본문 4.5:1에 미달합니다. 세 색 위에는 검정을 사용합니다. 보조 글자 그레이 600은 페이지 배경 위에서도 5.69:1입니다. 계산값은 소수점 둘째 자리 표시이며, 전체 페이지의 접근성 인증을 뜻하지는 않습니다.[5]

장식선과 조작 경계를 구분하기웜 그레이 300 / 흰색은 1.42:1이므로 장식선에만 사용합니다. 입력창처럼 경계 인지가 필요한 UI는 그레이 600이나 검정을 쓰고, 키보드 포커스는 검정 외곽선과 흰색 간격으로 표시합니다. 식별에 필요한 비텍스트 요소는 인접 배경과 3:1 이상을 확보합니다.[6]

운영 규칙 제안: 한 영역에서는 주된 강조색 하나를 선택합니다. 버튼 호버는 기존 색과 밑줄로 표현하고, 색을 계속 늘리지 않습니다. 노랑을 자동으로 ‘경고’에 배정하지 않습니다. 이 기본안에는 성공·오류 전용색과 다크 모드를 추가하지 않았습니다.

기존 컬러와 로고 설명은 첨부 자료 및 공식 CI를 기준으로 했습니다. 중립색 3개, 역할 배정, 변수명, UI 예시는 이번 리뉴얼을 위한 제안이며 공식 브랜드 규정이 아닙니다. 상단과 UI 예시의 기관명은 문서용 텍스트이며 공식 로고를 재제작한 것이 아닙니다. 운영 사이트에서는 승인된 로고 원본을 사용하세요.

파일은 HTML 하나로 구성되어 설치 없이 열 수 있습니다. Pretendard 웹폰트 로드에는 인터넷 연결이 필요하며, 연결되지 않으면 기기의 기본 고딕 글꼴로 표시됩니다. 외부 폰트 로드 외에 입력값을 전송하거나 저장하지 않습니다.
