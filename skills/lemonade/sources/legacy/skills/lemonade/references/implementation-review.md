# 디자인을 실제 화면과 동작으로 옮기기

HTML/CSS나 프런트엔드 코드를 구현·개선할 때 필요한 부분을 읽는다. 이미지 컨셉만 생성하는 작업에 코드·브라우저 절차를 추가하지 않는다.
이 자료는 [온실의 구현 기록](../../../examples/onsil/VERIFICATION.md)에서 드러난 문제와 검증 한계를 반영한다.
위 링크는 저장소 전체를 받을 때만 존재할 수 있다. 스킬만 설치해 예제가 없다면 `node <skill>/scripts/references.mjs --id local-onsil`의
저장된 관찰·검증 한계와 아래 요점을 사용한다. 없는 문서를 직접 열어보거나 예제를 다시 검증했다고 하지 않는다.

## 1. 구성 전에 행동의 정답을 정의

섹션별 과업·필수 필드·항목 수·행동·상태에서 작은 기대 결과 목록을 만든다. 코드가 만든 화면이 그 정답을 결정하지 않게 한다.
필터는 의도한 항목 ID/분류/개수, 예약은 실제 일정·가능 상태·가격·인원·선택 초기화, 링크는 실제 목적지를 검증한다.
같은 DOM을 읽어 예상 결과를 만들고 그 DOM과 비교하는 검사는 분류나 누락 오류를 독립적으로 확인하지 못한다.

온실의 3/2/1 필터 수와 2명 24,000원은 그 예제의 데이터다. 다른 프로젝트에는 그 프로젝트의 계약과 테스트 데이터를 사용한다.
달력 날짜는 존재하는 날짜인지, 기간 내인지, 휴관일인지, 회차가 가능한지 각각 확인한다.
날짜·프로그램을 바꾸면 종속 선택을 다시 검증하고 유효하지 않거나 오래된 선택·확인 결과를 지우며 금액을 다시 계산한다.
여전히 호환되는 선택을 유지할지는 해당 흐름의 계약으로 정한다. 온실은 날짜·프로그램이 바뀌면 회차를 항상 초기화하도록 설계했다.
지운 필수 값, 잘못된 값, 빈 결과, 매진·예정, 유효한 선택과 확인 완료도 구분한다.

## 2. 이미지를 불러온 뒤 실제 크기로 구성

`width`/`height`는 원본 비율과 레이아웃 예약을 돕는다. CSS로 너비만 바꿨다고 의도한 높이가 보장되는 것은 아니다.
전체 페이지에서 미디어가 인접 텍스트보다 불필요하게 길어지거나 빈 영역을 만드는지 확인한다.
자연스러운 이미지와 고정 크롭을 구분해 크기를 명시한다.

```css
/* 원본 비율을 보존하는 이미지 */
.natural-image { display: block; width: 100%; height: auto; }
/* 의도한 비율로 자르는 미디어 영역: 비율은 콘텐츠에 맞춰 선택 */
.cropped-media { aspect-ratio: 4 / 5; overflow: hidden; }
.cropped-media > img { width: 100%; height: 100%; object-fit: cover; }
```

예시의 4:5는 공통 규칙이 아니다. 포스터는 인식/내부 글자, 제품은 형태, 사진은 얼굴·행동·공간의 초점을 보존한다.
브레이크포인트마다 `object-position`과 높이를 확인한다. 정적 원본을 다시 생성해서 크롭 검토를 회피하지 않는다.
온실의 journal 이미지는 로딩과 넘침 검사에서 문제없어도 시각적으로 지나치게 길었다. 로딩 성공과 구성 품질은 다른 증거다.

## 3. 글꼴과 읽는 역할을 실제로 확인

설치·로딩된 font-face, 실제 한글/영문 glyph, 어절·문장부호·줄바꿈·행간을 구분한다.
`document.fonts.check()`의 통과만으로 화면의 모든 한글이 의도한 글꼴로 그려졌다고 판단하지 않는다.
대표 제목·본문·상태·긴 이름을 실제 렌더로 보고, 가능하면 브라우저의 실제 사용 글꼴 정보도 확인한다.

본문, 메타데이터, 상태, 버튼, 제목의 역할을 구분한다. 작은 라벨을 본문처럼 확대하거나 본문을 작은 메타데이터 크기로 축소하지 않는다.
본문 16–18px과 한글 행간 약 1.5–1.7은 시작값이다. 실제 언어·브랜드·읽는 길이에 맞게 확인한다.
390px뿐 아니라 768px 등 중간 너비에서 본문 규칙이 덮어씌워지는지 확인한다. 의미 있는 제목을 줄 수만으로 자르지 않는다.

## 4. 평상시 화면 밖의 상태도 설계

페이지 로딩 후 닫힌 메뉴와 모달만 확인하면 열린 상태의 문제를 놓친다.

| 상태 | 확인할 것 |
| --- | --- |
| 메뉴 펼침 | 목적지, 닫기, 키보드 이동, 현재 위치, 배경과의 대비 |
| UI를 열고 화면 크기 변경 | CSS와 JS 경계 일치, 가려진 토글/트리거, 초점의 위치 |
| 모달의 긴 내용·확인 결과 | 스크롤 후 제목·닫기가 닿는지, 확인 문구, 키보드 초점, 닫힌 뒤 복귀 |
| 필터 변경·빈 결과 | 선택 상태, 실제 결과, 설명, 목록 기준선과 페이지 밀도 |
| 값 지움·잘못된 선택 | 설명과 수정 경로, 종속 선택 재검증, 유효하지 않은 값·오래된 확인 제거, 금액 갱신 |
| 정상 선택·확인 | 표시한 데이터와 실제 처리의 일치, 정직한 완료 범위 |
| reduced-motion·본문 확대 | 콘텐츠·행동 보존, 겹침·잘림·넘침 |

스크롤되는 모든 UI에 sticky 제목을 강제하지 않는다. 닫기·주요 행동을 잃는 문제를 확인하고 그 UI에 맞는 방법을 선택한다.
네이티브 컨트롤도 실제 프로젝트의 Tab/Shift+Tab/Enter/Space/Escape 동작을 필요한 범위에서 확인한다.
포인터 자동 검사와 프로그램으로 입력값을 바꾸는 검사를 실제 키보드 조작처럼 보고하지 않는다.

## 5. 코드 검증과 시각 판단을 나란히

세 단계는 다른 질문을 확인한다.

1. **측정:** 깨진 자산, 실제 크기, 넘침·잘림·대비·글꼴 로딩과 같은 확인 가능한 상태.
2. **시각 판단:** 원본/참고와 비교한 위계·밀도·비율·크롭·한글 글줄·전체 리듬.
3. **과업:** 탐색 → 선택 → 상세/예약 → 수정/취소/확인을 실제로 수행.

데스크톱 전체 흐름·중요 영역 확대·모바일·중간 너비·열린/오류/성공 상태를 필요한 범위에서 확인한다.
각 관찰에는 너비·UI 상태·입력 방식·캡처/보고서·시점을 남긴다. 검사기의 resting-page 측정은 열린 모달 검증이 아니다.
비평은 [critique.md](critique.md)를 사용한다. reference 프로필의 경고는 유지/수정/보류 이유와 관련 증거를 기록한다.
동영상 없음, 반복 카드, 얇은 구조선, 브랜드 색, 의도된 다줄 제목만으로 실제 오류처럼 처리하지 않는다.
반대로 WARN이므로 무조건 괜찮다고 결론 내리지 않는다. 실제 글자가 작거나 과업이 불분명하면 고친다.

## 6. 수정의 증거와 범위를 보존

실패했던 보고서와 해당 캡처를 다음 실행 전에 별도 저장한다. 처음부터 전체 자료를 다 보관할 필요는 없지만 수정 원인을 재확인할 핵심 증거는 남긴다.
수정 뒤 관련 너비·상태·행동을 다시 확인한다. 예: 이미지 높이 변경이면 그 섹션과 인접 리듬, 본문 크기 변경이면 중간 너비와 줄바꿈,
모달 CSS 변경이면 열린 창·스크롤·포커스·닫기, breakpoint 변경이면 경계 전후의 열린 UI.
관계없는 성공 검사를 무조건 반복하지 않는다. 마지막에 통합 검사를 한 번 하고 결과를 기록한다.
같은 수정이 두 번 실패하면 멈추고 관찰한 사실과 남은 장애를 보고한다.

최종 PASS만 남았으면 이전 실패를 재현한 자료가 있다고 표현하지 않는다. 문서화된 작업 중 관찰과 저장된 자동 결과를 구분한다.
테스트 수, 0 FAIL, 자체 점수를 품질의 대체 지표로 사용하지 않는다. 미확인 너비·상태·입력·서비스를 밝힌다.

## 7. 자산과 전달까지 완성

프로젝트가 소비하는 이미지는 프로젝트 안에 저장하고 결과·프롬프트·생성/수집 출처를 기록한다. 생성 이미지를 실제 장소/고객 증거로 제시하지 않는다.
글꼴은 실제 출처와 라이선스를 유지한다. 로컬 실행을 요청했다면 런타임이 외부 CDN에 의존하는지 확인한다.
병렬 작업은 이미지/문서/모듈처럼 독립적인 소유 영역과 인터페이스를 정해 진행한다. 같은 파일·자산을 동시에 수정하지 않는다.

전달할 때는 실행 작업 디렉터리·명령·주소·종료 방법·필요한 도구를 README에서 쉽게 찾게 한다.
샘플 README만 깊게 숨겨져 있으면 저장소의 README에서도 링크나 실행 안내를 제공한다.
HTTP 모듈/데이터 로딩이 필요하면 `file://`로 열어도 동작한다고 하지 않는다. 서버를 종료했다면 접속 주소를 현재 실행 중인 미리보기처럼 제시하지 않는다.
실제 저장·예약·결제와 로컬 데모의 차이는 그 결정을 하는 흐름에서 설명한다.
