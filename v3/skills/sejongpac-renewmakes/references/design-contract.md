# 디자인 계약: 판단 기준과 구현 기준

## 1. 무엇을 개선하는가

방문자가 프로그램을 고르고, 예매 내역을 확인하고, 찾아오는 길과 접근성을 확인하는
문화시설 프런트엔드다. 비공식 리뉴얼이며 인증·결제·티켓 발행·실제 기관 접수를 하지 않는다.
관심·체험 프로필·예매·신청은 브라우저 저장소 기반이다. 이 경계를 숨기지 않는다.

이 사용자가 원하는 ‘사람이 디자인한 것 같은 미니멀 UI’의 관찰 가능한 기준은 다음과 같다.

| 평가 축 | 통과하는 형태 | 이 대화에서 거부된 형태 |
| --- | --- | --- |
| 위계 | 실제 중요도에 맞는 큰 메뉴와 읽히는 그룹명 | 12px 회색 그룹명과 14px 모바일 링크 |
| 반복 | 목적별 그룹과 단정한 링크 | 같은 아이콘 박스·설명·화살표 카드 4개 |
| 장식 | 실제 정보·설명·안내 링크 | 작은 민트 점·중복 영문 머리말 (하단 큰 도형은 최신 지시로 보존) |
| 인터랙션 | 실제 목적지·선택·누름·초점·재생 상태 | 가짜 버튼, 들뜸 효과만 있는 링크 |
| 알림 | 화면을 막지 않는 완전한 캡슐 토스트 | border-radius가 없거나 거의 각진 상태 알림 |
| 체계 | 같은 역할에 같은 토큰과 shared CSS | 페이지마다 작은 임의 수치·서로 다른 알림 모양 |

‘AI스럽다’는 표현을 모든 장식·원·영어가 절대 금지라는 추상 규칙으로 바꾸지 않는다.
사용자가 거부한 역할과 맥락을 식별해 제거한다. 특히 유용하지 않은 공간 채우기 장식은
다른 문구나 도형으로 대체하지 않는다.

## 2. 글자·간격·색상

### 글자

브라우저 기본 크기 16px에서의 역할별 값:

| CSS token | 값 | 적용 |
| --- | --- | --- |
| `--text-sm` | 1rem = 16px | 보조 정보, 분류, 날짜, 상태, 고지 |
| `--text-body` | 1.125rem = 18px | 기본 본문 |
| `--text-lead` | 1.25rem = 20px | 배너 하단 안내 |
| `--text-action` | 1.375rem = 22px | 빠른 메뉴 |
| 모바일 `--text-action` | 1.25rem = 20px | 600px 이하 빠른 메뉴 |
| `--text-item-title` / `--text-card-title` | 1.25rem = 20px | 방문 안내 항목 / 포스터 제목, weight 650 |
| `--text-meta` | 1rem = 16px | 카드 분류·상태·날짜·장소 |
| `--text-heading` | clamp(1.75rem, 3vw, 2.5rem) | 신규 중간 제목 기본 |

가독성 검토에서는 최소값만 확인하지 않는다. 중요한 링크와 본문의 위계가 충분히
구분되는지, 줄 길이와 실제 한글 글꼴이 적절한지 함께 본다. 큰 제목을 16px로
평준화하거나 모든 본문을 큰 제목처럼 키우는 것이 아니다.

body/label/action/title/heading 굵기는 400/500/600/650/720을 토큰으로 관리한다.
body 행간 1.7, label 행간 1.5다. 새 코드에는 role token을 사용한다.

작은 화면에서 공간이 부족하면 다음 순서로 바꾼다.

1. 여백과 중복 콘텐츠를 점검한다.
2. 문구가 기능을 잃지 않도록 불필요한 수식을 줄인다.
3. 줄바꿈, 단일 열, 그룹 재배치를 사용한다.
4. 표·좌석도처럼 본래 넓은 정보는 의미 있는 내부 스크롤을 제공한다.
5. 일반 UI 글자를 16px 미만으로 줄여 맞추지 않는다.

이미지 안에 원래 들어 있는 포스터 글자, 정보 지도·도형의 글자는 일반 UI 최소 크기
검사와 구분한다. 이 구분을 이용해 HTML 레이블을 SVG에 넣어 작게 만드는 우회는 하지 않는다.

### 간격과 색상

- 4/8/12/16/24/32px 기반 `--space-*` 토큰을 사용한다.
- 종이색·잉크색은 흰색과 검정. muted도 읽히는 대비를 유지한다.
- 천 `#54c8e8`, 지 `#c36d15`, 인 `#ffe800`은 독립 브랜드 채널이다.
- 브랜드색이라는 이유로 의미 없는 점을 붙이지 않는다.
- 밝은 브랜드색 위에는 읽기 쉬운 검정 글자를 사용한다.
- 선택 상태를 색상만으로 전달하지 않는다. 텍스트·모양·aria 상태를 함께 갱신한다.
- 로컬 Pretendard Variable을 사용한다. 외부 폰트 CDN을 새 의존성으로 넣지 않는다.

## 3. 빠른 메뉴

현재 정보 구조:

| 그룹 | 링크 | 해시 경로 |
| --- | --- | --- |
| 일정·예매 | 공연 일정 | `#/programs?view=calendar` |
| 일정·예매 | 예매 확인 | `#/account/bookings` |
| 방문 안내 | 오시는 길 | `#/visit/directions` |
| 방문 안내 | 관람 안내 | `#/visit/accessibility` |

빠른 링크 전체는 `<nav aria-label="빠른 서비스">`, 각 묶음은 label과 ul/li/a로 구성한다.
링크는 실제 href를 가진다. 텍스트 주변 여백도 클릭 가능하며 최소 높이는 64px다.

아이콘은 desktop 26px, mobile 24px로 읽히는 텍스트와 맞춘다.
배경 박스를 다시 추가하지 않는다. 현재 미니멀 UI의 기본 바탕은 흰색이며
상태 배경은 hover/pressed 때만 나타난다.

모바일은 두 그룹을 세로로 놓고 각 그룹 안 링크는 공간에 맞게 배치한다.
현재 auto-fit/minmax의 rem 기반 최소값은 글자 설정에 대응하기 위한 선택이다.
320px에서도 링크와 레이블이 겹치지 않는지 검사한다.

## 4. 상호작용

### 상태 표

| 상태 | 구현·검증 |
| --- | --- |
| default | 장식 없는 링크와 충분한 여백 |
| hover | `--state-hover: #f0f2f4`, 정적 밑줄 |
| pressed | `--state-pressed: #e1e5e9` |
| keyboard focus | 3px outline, 4px offset; DOM 순서와 시각 순서 일치 |
| favorite off/on | outline/filled Material 심볼, aria-pressed, 저장 상태 일치 |
| disabled | 실제 조작 불가와 시각 표현 일치 |
| feedback | 실제 결과를 설명하는 캡슐 토스트 |

`:hover`가 `:active`를 덮을 수 있다. 현재 구현의 `:hover:not(:active)`처럼
상태의 우선순위를 명확히 하고 실제 pointer down 상태를 측정한다.
마우스 이동 전후의 y좌표도 비교해 hover-lift가 없는지 확인한다.

toast 진입·모달 등장·배너의 기능적 전환은 필요한 모션이다. 버튼이 불쑥 솟는
장식 모션과 구분한다. ‘모든 transform 제거’로 배너·토스트의 작동까지 깨뜨리지 않는다.

### 배너

- 주요 프로그램 3개, 2700ms 시작 간격으로 왼쪽 이동, 800ms 전환을 사용한다.
  이전의 3초/700ms는 폐기되었다. 양방향 pointer drag와 650ms shade/copy fade를 제공한다.
- current / total 숫자는 수동·자동·이전·다음 모두 실제 active index와 맞춘다.
- 재생 토글의 icon, action label, aria-pressed를 일치시킨다.
- 수동 이동만 live region에 순서와 작품명을 알린다. 자동 이동을 반복 낭독하지 않는다.
- 키보드 ArrowLeft/Right, reduced motion, hover·visibility·focus에 따른 재생 중단을 검토한다.
- 화면 밖·문서 숨김에서 재생을 멈추고 route cleanup에서 timer/observer를 정리한다.
- 모바일에서도 안내 문구를 작게 하거나 숨기지 않고 조작부를 새 줄로 배치한다.

## 5. 문구·도형·사진

장식 후보마다 다음의 결과를 기록한다.

| 질문 | 판단 |
| --- | --- |
| 사용자가 행동하거나 정보를 이해하는 데 필요한가? | 필요하면 실제 정보로 유지 |
| 바로 아래 한국어 제목/본문을 영문으로 반복하는가? | 중복 머리말 제거 |
| 지명·연도·영문 조합으로 빈 곳만 채우는가? | 제거 |
| 작은 민트 점·원에 상태·지표·설명 의미가 있는가? | 없다면 markup/pseudo-element 모두 제거 |
| 사진 자체와 alt/주변 문맥으로 이미 아는 내용을 반복하는가? | caption 제거 |
| 출처·저작권·작품명처럼 식별에 필요한가? | 정확한 caption/문서로 유지 |

이미 제거한 문자열을 다시 디자인 재료로 쓰지 않는다.

- 홈: `광화문, 세종문화회관`, `SEOUL · SINCE 1978` 사진 caption.
- 소개: `SINCE 1978 · GWANGHWAMUN, SEOUL`, `A PLACE FOR EVERYONE`.
- 소개 사진의 반복 주소 caption.
- 소개의 `HEAVEN · EARTH · HUMAN`, `OUR RESPONSIBILITY` 중복 eyebrow.
- 홈에서 한국어 제목 앞을 채우던 반복 kicker 문구와 영문 identity 머리말.

한 페이지에서 제거한 뒤에는 같은 component, 인접 섹션, 다른 viewport에도 같은
문제가 남았는지 확인한다. 이번 about 잔존은 홈 수정만으로 정책이 적용되지 않은 사례다.
문서에 정책을 쓰는 것과 실제 코드에 적용하는 것은 별도 작업이다.

실제 길찾기 주소, 역사 속 1978년, footer 기관 정보, 천·지·인 설명과 안내 링크,
비공식·체험·접근성 고지는 위 제거 대상과 다르다. 보존 이유를 구체적으로 설명할 수 있어야 한다.
**소개 하단의 큰 민트 원과 천지인 도형 패널은 최신 사용자 지시로 보존한다.**
이미 제거되었다면 해당 부분만 git restore로 정밀 복구한다. 이전 제거 방침은 이 부분에서
폐기되었다. 제목 옆 작은 도형과 OPEN/WITH/GIVE 같은 반복 태그·중복 영문·주소 캡션은
계속 제거 상태다. PLAN YOUR VISIT와 같은 역할의 문구를 전체 경로에서 조사한다.
체험 고지는 삭제하지 않고 색 띠·회색 네모 박스 없이 읽히는 본문으로 제공한다.

## 6. 알림·모달·radius

### 비차단 상태 알림

`관심 프로그램에서 삭제했어요.`가 뜨는 `#toast`는 status feedback이다.

- shape: radius 9999px, 완전한 캡슐 끝.
- font: 최소 16px, 대비 있는 바탕과 글자.
- min-height: 48px, 충분한 좌우 padding, viewport 안의 max-width.
- accessibility: role=status, aria-live=polite.
- behavior: 실제 삭제 상태 반영, 3.5초 뒤 자동 닫힘, focus 유지.
- shared implementation: `assets/ui-feedback.css`를 legacy/v2에서 함께 load.

`border-radius: 100%`는 가로·세로 반경이 길이에 따라 달라 긴 타원처럼 될 수 있다.
사용자의 ‘100% 최대’는 시각적 캡슐 의도이며, 큰 동일 길이 반경을 선택하는 이유다.
한 줄 짧은 문구와 320px에서 여러 줄이 된 문구를 둘 다 본다.

### 큰 dialog

검색/전체 메뉴처럼 실제 모달은 24px radius token을 사용한다.
모바일 규칙이 다시 16px로 줄이지 않도록 확인한다. 거의 각진 모서리를 허용하지 않는다.
배경막, 적절한 labelled dialog, Escape, 닫기, 초점 복귀를 유지한다.

알림의 캡슐 반경과 큰 모달의 24px는 **요소 역할을 구분한 일관성**이다.
모든 박스에 같은 숫자를 붙이는 것이 일관성이 아니다.

## 7. 변경 검토표

- 읽는 순서, 글자 역할, computed size와 실제 한글 글꼴을 확인했는가?
- 빠른 메뉴의 4개 목적지와 각 상태가 실제로 작동하는가?
- hover/pressed/focus가 서로 구별되고 요소가 움직이지 않는가?
- 의미 없는 영문 머리말·지명·연도·색점·중복 caption을 제거했는가?
- alt·기관 정보·출처·비공식 고지를 보존했는가?
- toast와 dialog의 shape, semantics, focus, dismissal이 역할에 맞는가?
- desktop/mobile, legacy/v2, 일반/선택 상태 사이에 의미 없는 차이가 없는가?
- 토큰·공통 CSS·문서·검사가 같은 수치와 정책을 가리키는가?
- 사용자의 이번 지적을 적용한 화면 외에 같은 실수가 남은 공통 component를 봤는가?

공통 카드, 포인터 입력, 복구 절차의 세부 계약은 [최신 추가 계약](cards-and-restoration.md)을 따른다.
