# limsflex 코드·웹표준 계약

디자인 선택은 자유롭다. 아래 기준은 표현을 제한하는 스타일 가이드가 아니라, 사람이 읽고 브라우저가 안정적으로 처리할 코드의 계약이다. 작업 범위의 신규·수정 코드에 적용하며 관계없는 기존 파일을 일괄 포맷하지 않는다.

## 들여쓰기와 이름

HTML은 DOM 중첩마다 공백 4칸을 사용한다. 짧은 태그는 읽기 좋으면 한 줄에 둔다. 긴 태그는 속성을 한 줄씩 나누고, 속성을 시작 태그보다 4칸 들여쓰며 닫는 `>`는 시작 태그와 정렬한다.

```html
<form class="search-form" action="/search" method="get">
    <label for="search_query">검색어</label>
    <input
        type="search"
        id="search_query"
        name="q"
        autocomplete="off"
    >

    <button type="submit" class="search-btn">검색</button>
</form>
```

새 클래스는 소문자 영문과 숫자로 단어를 만들고 `-`로 연결한다. `input-box`, `close-btn`, `has-error`처럼 역할·상태를 표현한다. 같은 역할에는 기존 클래스명을 재사용한다. 외부 라이브러리 클래스와 기존 공용 `.sr-only` 등은 의존 관계를 깨뜨리며 바꾸지 않는다. 새 제공 기본 CSS에서는 `.sr-only`를 사용한다.

CSS는 `<style>` 안에서도 최상위 선택자를 첫 칸에 둔다. 선언 한 줄에 하나, 콜론 뒤 공백 하나, 마지막 선언까지 세미콜론을 사용한다. 각 블록은 빈 줄 하나로 구분한다. 불필요한 빈 줄·설명용 주석을 반복하지 않는다. JavaScript를 작성한다면 블록 중첩마다 공백 4칸을 사용한다.

```html
<style>
:root {
    --content-width: 72rem;
}

.card-list {
    display: flex;
    flex-wrap: wrap;
    gap: 24px;
}

.product-card {
    flex: 1 1 18rem;
    min-width: 0;
}

.product-card.is-muted {
    opacity: 60%;
}

@media (min-width: 900px) {
    .card-list {
        gap: 32px;
    }
}
</style>
```

CSS는 기반·토큰, 문서 전체, 주요 영역, 컴포넌트, 상태, 반응형 조정 순서로 정리한다. 기존 프로젝트의 정리 방식이 있으면 유지한다.

## 기본 CSS와 캐스케이드

- 기본 CSS를 먼저, 페이지·컴포넌트 CSS를 나중에 적용한다. 파일이 존재하고 실제 진입점에서 로드되는지 확인한다.
- 적합한 기존 기본 CSS를 재사용한다. 없으면 `../assets/default.css`를 복사하거나 프로젝트용 기본 CSS를 만든다. 이 링크는 이 문서 기준의 스킬 내부 위치이며 완성 페이지의 URL이 아니다.
- 제공 CSS는 수정 가능한 기반이다. 디자인과 실행 환경에 맞게 추가·삭제·재구성해도 된다. 기존 공용 CSS를 수정한다면 사용하는 페이지에 미치는 영향을 확인한다.
- reset과 페이지 스킨을 구분한다. 사이트 전체의 링크 장식, 목록 마커, 폼 외관, 가로 스크롤을 무차별하게 없애지 않는다. 필요한 컴포넌트 범위에서 재정의한다.
- `!important`를 일반적인 선택자 우선순위 조절에 사용하지 않는다. 제공 CSS의 `hidden` 보호처럼 기반 동작을 보장하는 용도는 유지할 수 있다.
- 넓은 자손 선택자로 중첩된 요소까지 의도치 않게 꾸미지 않는다. 관계에 맞는 클래스나 자식 선택자를 사용한다. 가상 요소와 SVG 자체의 색상·투명도를 확인하고 아이콘 중복과 이중 opacity를 방지한다.

## HTML과 네이티브 조작

- 독립 페이지에는 `<!DOCTYPE html>`, 올바른 `lang`, UTF-8, 내용을 나타내는 `title`, viewport를 포함한다. viewport로 확대를 막지 않는다.
- 요소는 의미에 따라 선택한다. 페이지 주제의 제목과 제목 계층, 주 콘텐츠의 `main`, 필요한 `header`·`nav`·`footer`를 적절히 사용한다. 제목 없는 시각적 컨테이너에는 `div`를 사용할 수 있다. 모든 프레임을 `section`으로 만들지 않는다.
- 요소의 콘텐츠 모델을 지킨다. `p`에 블록 요소를 넣지 않고 `ul`·`ol`의 항목에는 `li`를 사용한다. 링크나 버튼 안에 다른 조작 요소를 넣지 않는다. ID는 문서 안에서 유일해야 한다.
- 이동에는 유효한 `href`가 있는 `a`, 조작에는 `button`, 입력에는 적절한 `input`·`select`·`textarea`를 사용한다. 가짜 `href="#"`나 클릭 전용 `div`로 기능을 대신하지 않는다.
- 폼 안의 제출 외 버튼에는 `type="button"`을 지정한다. 폼에는 실제 목적에 맞는 `name`·`type`·`autocomplete`와 필요한 `required` 등을 설정한다.
- 입력에는 연결된 레이블을 제공한다. placeholder를 레이블 대신 쓰지 않는다. 선택지 그룹에는 필요에 따라 `fieldset`과 `legend`를 사용한다.
- 실제로 선택하는 체크 항목에는 checkbox를 사용한다. 단순 조건이나 상태의 목록에는 리스트를 사용하고, 시각적 체크 아이콘만으로 입력 요소를 결정하지 않는다.
- 장식 이미지에는 빈 `alt`, 정보 이미지에는 내용에 맞는 `alt`를 제공한다. 장식 SVG는 보조 기술에서 숨기고 아이콘만 있는 버튼에는 `.sr-only` 텍스트 등으로 이름을 부여한다.
- 조작할 수 없는 네이티브 컨트롤에는 실제 `disabled`를 사용한다. `aria-disabled`를 사용한다면 조작 차단도 구현한다. ARIA 상태는 실제 상태와 일치해야 한다.
- 필요한 네이티브 기능이 있으면 먼저 선택한다. ARIA만 붙인 커스텀 컨트롤에 키보드 동작이 자동으로 생기지는 않는다.

## 관련 콘텐츠 그룹과 URL fragment

관련 콘텐츠를 의미에 맞는 컨테이너로 묶는다. 제목 있는 주제는 `section`, 독립 콘텐츠는 `article`, 탐색은 `nav`, 나란한 항목은 `ul`/`ol`, 관련 폼 입력은 `fieldset`과 `legend`를 사용한다. 시각적 래퍼를 모두 section으로 바꾸지는 않는다.

의미 있는 그룹 컨테이너마다 목적을 나타내는 고유하고 안정적인 kebab-case `id`를 부여한다. 기존 fragment ID와 label/ARIA 연결을 유지하고, 재정렬 시 바뀌는 번호나 무작위 ID는 피한다. 반복되는 그룹은 안정적인 콘텐츠 식별 기준으로 ID를 구분한다.

```html
<a href="#features">주요 기능으로 이동</a>

<section id="features" class="feature-section">
    <h2>주요 기능</h2>
    <p>같은 주제의 관련 콘텐츠를 이 안에 배치합니다.</p>
</section>
```

같은 페이지에서는 `href="#features"`, 다른 페이지에서는 `page.html#features`로 연결한다. 실제 앵커 이동이 URL의 fragment를 갱신하며, `id`만 추가하면 현재 URL이 자동으로 바뀌지는 않는다. URL을 바꾸지 않고 스크롤만 하는 가짜 링크로 대체하지 않는다. 정적인 fragment 이동에는 JavaScript가 필요 없다.

ID 중복·링크 대상 일치·fragment 직접 진입·새로고침·뒤로/앞으로 이동을 확인한다. 고정 또는 sticky 헤더가 대상을 가리면 실제 헤더 높이에 맞는 `scroll-margin-top`을 대상에 적용한다.

## Flexbox·Grid·반응형

- 한 축의 배치, 정렬, 크기 조절에는 Flexbox를 우선한다. 행과 열을 동시에 관리하는 구조에는 Grid가 적합하다. 일반 흐름의 텍스트에 불필요한 flex 래퍼를 만들지 않는다.
- 간격에는 `gap`, 정렬에는 `align-items`·`justify-content` 등을 사용한다. 빈 요소, 연속 공백, 고정 `top`·`left` 값으로 위치를 맞추지 않는다.
- flex item의 기본 최소 크기로 긴 내용이 넘친다면 대상에 `min-width: 0`(논리 방향에서는 `min-inline-size: 0`)이나 줄바꿈을 설정한다. 세로 스크롤 영역에는 필요에 따라 `min-height: 0`을 사용한다. 이미지 비율이나 버튼 글자를 찌그러뜨리지 않는다.
- 여러 항목을 좁은 폭에 배치하려면 적절한 `flex-wrap`, 최대 폭, 콘텐츠에 맞는 미디어쿼리를 사용한다. 긴 단어·URL·번역문도 확인한다.
- DOM의 읽기·키보드 순서는 의미 있는 순서를 유지한다. `order`나 `row-reverse`만으로 의미 있는 순서를 바꾸지 않는다.
- 절대 배치와 겹침은 장식·국소 오버레이 등 필요한 표현에 사용할 수 있다. 주요 본문·폼·카드 전체를 고정 좌표로 조립하지 않는다.
- 가로 넘침을 `html, body { overflow-x: hidden; }`으로 숨기지 말고 원인을 수정한다. 표처럼 의도적으로 폭이 필요한 콘텐츠는 필요한 영역에만 접근 가능한 스크롤을 제공한다.
- 특정 브랜드의 `360px` 최소 폭이나 `390px` 고정 폭을 가져오지 않는다. 대상 디자인에 맞게 좁은 화면부터 넓은 화면까지 배치한다. 필요한 고정 폭도 좁은 화면에서 콘텐츠가 손실되지 않게 처리한다.

## 접근성과 동작

- 마우스 외 방법으로도 조작할 수 있고 포커스 위치가 보여야 한다. 대체 표시 없이 `outline`을 지우지 않는다. Tab·Shift+Tab과 해당 컨트롤에 필요한 Enter·Space·방향키 동작을 확인한다.
- 상태와 오류를 색만으로 전달하지 않는다. 필요한 텍스트와 `aria-describedby`·`aria-invalid` 등으로 관련 정보를 연결한다. 동적 알림에는 목적에 맞는 live region을 사용한다.
- 대비를 확인한다. WCAG 2.2 AA 기준을 적용해 일반 텍스트는 4.5:1, 큰 텍스트(18pt 이상 또는 굵은 14pt 이상)는 3:1, 필요한 UI 경계·상태 표시는 3:1을 확보한다. 비활성 컨트롤 등 표준의 예외도 구분한다. 이미지 배경과 hover 등 실제 상태를 함께 확인한다.
- 확대와 글자 크기 변경으로 글자·조작 요소가 잘리지 않아야 한다. 320 CSS px 상당의 좁은 폭과 200% 확대를 확인하고, 400% 확대에서의 리플로도 확인한다. 이차원 표시가 필수인 콘텐츠 외에는 불필요한 양방향 스크롤을 피한다.
- 애니메이션 표현은 자유롭게 선택한다. `prefers-reduced-motion: reduce`에서는 장식적 이동이나 연속 애니메이션을 멈추거나 줄이고 필요한 상태 변화는 이해할 수 있게 남긴다. 기본 CSS만으로 컴포넌트의 모션 대응이 끝났다고 판단하지 않는다.
- 모달 등을 구현할 때는 열기·닫기, 포커스 이동·복귀, 필요한 키보드 조작도 구현한다. 정적 디자인 확인 화면에 동작을 완성한 것처럼 보이는 가짜 처리를 추가하지 않는다.

## 전달 전 확인

대상 코드의 공백·클래스명, HTML 구조, 기본 CSS의 로드 순서와 실제 경로, 기존 선택자 범위를 확인한다. 가능하면 프로젝트의 HTML/CSS 검사와 브라우저 검증을 수행한다. 표준에 없는 문법이나 대상 환경에서 사용할 수 없는 기능에는 대안을 제공한다.

브라우저에서 좁은 폭·넓은 폭·긴 문장·확대·키보드·모션 설정, 요청한 동작과 상태를 확인한다. 수행한 검증과 수행할 수 없었던 검증을 구분해 보고한다. 완성 코드나 대상 파일을 먼저 제공하고 필요한 범위만 설명한다.

사양을 확인할 필요가 있으면 아래 일차 자료를 참조한다. 4칸 들여쓰기와 kebab-case는 이 스킬의 코드 규약이며 HTML/CSS 사양 자체의 요구사항은 아니다.
