# 미구현 페이지 한정 완성 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:dispatching-parallel-agents for independent content domains; integrate and verify the shared database and rendering changes in the parent session.

**Goal:** 공통 안내문에 머물러 있는 89개 페이지를 실제 정보·목록·비교·신청 화면으로 완성한다.

**Architecture:** 기존 98개 안내 경로 중 실제 목록·검색이 있는 9개는 보호한다. 나머지 89개만 명시적 허용 목록으로 새 렌더러에 연결하고 기존 공통 컴포넌트를 조합한다. 상세 콘텐츠는 기존 Supabase `sejong_pages.payload.completion`에 추가하며 신청·문의는 별도의 RLS 테이블과 검증 RPC로 저장한다.

**Tech Stack:** Next 14.2.35, React 18, TypeScript, 기존 디자인 시스템, Supabase Postgres/Auth, Playwright.

**Spec:** 사용자 제공 62쪽 분석 PDF의 kordoc 파싱 결과와 최신 지시. 임시 안내 페이지 포함, 이미 완성된 페이지 수정 금지, 자체 DB 접수.

## Global Constraints

- v5만 수정. 기존 홈·프로그램 목록/상세·회원·예매·소개·메뉴·디자인 토큰과 기존 컴포넌트 구현은 변경하지 않는다.
- 라우터에는 정확한 대상 89개에 대한 분기만 추가한다. 디자인 등록부에는 새 구현만 추가한다.
- 모든 텍스트는 기존 `data-text`/SystemText, 최소 16px. 기존 CSS 변수·곡률·안쪽 스트로크를 사용한다.
- 외부 자료는 공식 원문으로 확인하고 출처·확인일을 기록한다. 가격·일정·직책·접수 상태·판매 재고를 만들지 않는다.
- 자체 DB 저장과 결제·발권을 구분한다. 실제 PG가 없는 상태에서 결제 완료를 만들지 않는다.
- 새 데이터 파일은 SQL 수입 원본이다. 제품은 DB에서 생성한 스냅샷과 공개 갱신을 사용한다.
- 리셋·강제 푸시 없이 main에 소스·전체 out·미러를 함께 커밋하고 두 원격에 일반 푸시한다.

## Review Focus

- 기존 페이지 침범: 보호 파일의 해시와 대상 외 DB payload가 변경되지 않아야 한다.
- 잘못된 기관 정보: 출처 없는 사람·혜택·가격·모집 상태를 노출하거나 접수를 열지 않는다.
- 신청 오류: 미인증·중복 재시도·계정 전환·오프라인·취소 경합에서 가짜 성공이 없어야 한다.
- 반응형: 320·390·768·1024·1440px에서 표·필터·폼이 넘치거나 16px 미만이 되지 않아야 한다.
- 연결: 모든 새 공개 컴포넌트가 실제 제품 경로와 가이드 등록에 연결돼 등록 수와 제품 연결 수가 같아야 한다.
