# v5 컴포넌트 연결과 규격 통합

기존의 디자인 가이드 전용 예제와 제품의 별도 마크업을 연결합니다. 색상·서체·레이아웃·콘텐츠를 보존하면서 같은 역할의 컨트롤은 공통 구현을 사용하고, 목적이 다른 표현은 베리언트로 관리합니다.

## 단일 기준

`src/data/design-tokens.ts`가 색상, 서체, 위계, 간격, 곡률, 모션, 유리 재질의 원본입니다. 생성한 `styles/tokens.css`와 가이드의 CSS 다운로드가 같은 정의를 사용합니다. 생성 파일만 직접 수정하면 검사가 실패합니다.

| 역할 | 최소 높이 | 곡률 |
| --- | --- | --- |
| 기본 버튼·입력 | 48px | 8px |
| flow 버튼 | 50px | 9px |
| flow 입력 | 54px | 9px |
| 원형 아이콘 버튼 | 48px | 원형 |

유리 재질은 `surface`(0.82/64/18/32), `drawer`(0.94/96/24/40), `hero`(0.84/72/20/28)를 사용합니다. 숫자는 불투명도·굴절·흐림 px·두께 px 순서입니다. 가이드 실험 도구를 제외한 제품은 재질 수치를 각자 지정하지 않습니다.

`className`은 배치와 문맥에 필요한 연결을 보존합니다. 페이지 CSS에서 공통 컨트롤의 색·높이·곡률을 다시 정하는 대신, 필요한 차이를 공통 베리언트에 추가하고 제품과 가이드에서 함께 검증합니다.

## 실제 연결

- 버튼·링크·원형 조작·필터·입력·체크박스·상태 표시를 제품과 가이드에서 공유합니다. 필터는 `aria-pressed`, 실제 탭은 탭·패널 및 방향키 탐색을 사용합니다.
- 검색과 문서 대화상자는 `SystemDialog`의 초점·스크롤 잠금·닫기 동작을 사용합니다. 자유 이동 유리 메뉴는 별도의 비차단 `FloatingPanel`로 남깁니다.
- 히어로, 시즌 배너, 예매 달력, 프로그램 선택 타일은 추출한 실제 컴포넌트를 가이드에서도 사용합니다. 대표 프로그램 데이터도 제품과 예제가 공유합니다.
- 홈 제목은 `BookingInvitation`에 현재 문구 ‘관람 예약’을 전달하며 앵커 ID를 유지합니다.
- `Toast`는 알림 호스트와 호출 함수의 호환 별칭이며 별도 컴포넌트로 중복 집계하지 않습니다. 사용하지 않던 `SejongApp` 연결 파일만 제거하고 보존된 구버전 소스는 유지합니다.

## 등록과 검사

`src/data/component-registry.ts`는 구현·문서·베리언트·상위 구성 요소를 연결합니다. `scripts/audit-component-system.ts`는 실제 export와 JSX 사용 경로를 분석해 사용 현황을 생성합니다. 파일 전체를 사용 중으로 간주하지 않으므로 같은 모듈의 문서 전용 컴포넌트가 제품 사용으로 잘못 집계되지 않습니다.

새 컴포넌트는 소스와 공개 이름, 역할, 가이드 위치를 등록합니다. 내부 지원은 상위 컴포넌트를 명시하고, 문서 도구와 페이지 전용 연결은 UI와 구분합니다. 가이드의 전체 컴포넌트 목록은 이 등록부와 분석 결과를 사용합니다.

현재 분석 결과는 등록된 구현 **46개**, 제품 연결 **43개**, 가이드 전용 **3개**, 미사용 **0개**입니다. `HeroCarousel`은 등록된 `HeroSlide`·`HeroCompanion`·공통 조작 버튼을 조합하며, 사진 위 조작은 `inverse-quiet` 베리언트를 공유합니다. 마이페이지의 공간·멤버십·티켓·관람노트·조합 화면을 등록했고 `SystemTabs`를 실제 계정 패널에 연결했습니다. 가이드 전용 항목은 문서 도구 `LiquidGlassDemo`, `ComponentCatalog`와 Deprecated로 보존한 `BookingInvitation`입니다. 프로그램의 분류 선택은 `SystemFilterButton`을 유지합니다.

달력 날짜 셀, 좌석 지도, 포스터를 포함한 프로그램 선택은 소유 구현·태그·`data-system-part`·이유를 명시한 예외입니다. 일반 버튼이나 입력을 다시 작성할 수 있도록 파일 전체를 예외로 두지 않습니다.

## 실행과 검증

- `npm.cmd run check:system`: 생성 CSS·사용 현황·등록·예외·직접 작성한 일반 컨트롤을 검사합니다.
- 개발과 빌드의 사전 단계에서 토큰·컴포넌트 분석을 실행합니다. 오류가 있으면 시작을 중단합니다.
- `node tests/component-system-browser.ts <v5 URL>`: 5개 너비에서 제품과 가이드의 기본형·flow형 규격, 입력 흐름, 검색 모달, 등록 목록과 앵커를 확인합니다.
- 기존 티켓오픈·이미지·하트·알림·모바일 유리 메뉴 검사를 함께 유지합니다. 정적 빌드와 루트 미러도 동일한 파일을 포함해야 합니다.

회원·예매의 보존 CSS는 `data-component="field"`인 공통 필드를 제외합니다. 크기뿐 아니라 포커스·오류·비활성 상태와 전환 시간도 제품과 가이드가 같은 구현에서 얻습니다. 가이드 전용으로 남아 있던 버튼·입력·상태·탭 스타일 중복도 제거했습니다.

기존 통합 작업의 검증 결과는 `docs/verification/component-system.json`과 관련 브라우저 보고서에 저장되어 있습니다. 해당 시점에는 단위 검사 83개 통과, 실패 0개, HTML 155개와 산출물 8,288개의 미러 일치를 확인했습니다. 마이페이지·OAuth 추가 검증은 `docs/verification/account-space.json`·`account-auth.json`에서 별도로 관리합니다. 보존된 v4의 별도 브라우저 검사는 기본 실행에서 제외됩니다.
