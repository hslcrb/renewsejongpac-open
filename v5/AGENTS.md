# v5 작업과 통합 규칙

## 브랜치

- **사람과 모든 에이전트는 작업별 브랜치를 반드시 사용한다. main 직접 작업 지침은 2026-10-23의 브랜치 필수 규칙으로 대체한다.**
- 동시 작업은 고유 브랜치와 별도 worktree/clone으로 분리한다. 공유 작업폴더에서 다른 작업자의 브랜치를 전환하지 않는다.
- 시작할 때 상태와 원격을 확인하며 기존 사용자 변경을 보존한다. reset과 강제 푸시는 사용하지 않는다.
- 검증한 소스와 필요한 전체 정적 빌드·미러 산출물을 작업 브랜치에 커밋하고 `git push -u origin HEAD`로 일반 푸시한다. 검토한 작업은 main에 `git merge --no-ff <branch>`로 통합한 뒤 `git push origin main`을 실행한다.
- 공통 절차는 [CONTRIBUTING.md](../CONTRIBUTING.md), 모델용 참조는 [LLM_REFERENCE.md](../LLM_REFERENCE.md)를 따른다.

## 디자인과 구현

- 현재 디자인 시스템의 등록 컴포넌트를 수정·조합한다. 같은 역할의 컨트롤을 페이지에서 새로 만들거나 토큰을 뒤늦게 덮어쓰지 않는다.
- 모든 실제 UI 텍스트는 `SystemText` 또는 공통 `data-text` 속성에 연결하며 데스크톱 최소 16px를 지킨다. 반응형에서도 크기를 줄여 해결하지 않는다.
- 색상은 단일 TypeScript 컬러 정의에서 생성한 CSS 변수만 사용한다. 옅은 노랑의 오프화이트와 갈색이 아주 조금 섞인 오프블랙, 부드러운 스트로크를 유지한다.
- 반복되는 둥근 표면은 `SystemSurface`로 조합한다. 공통 프레임은 넓게 사용하고 문단·입력 양식의 읽기 폭은 별도로 둔다.
- 개인 공간·관심 공연·관람노트·예매 기록은 인증한 계정의 Supabase DB를 사용한다. 로컬 저장을 성공한 DB 저장으로 가장하거나 저장 실패를 숨기지 않는다.
- 홈 ‘관람 예약’은 정적인 제목이다. `BookingInvitation`은 퇴역했으며 가이드에 `Deprecated` 이력만 남긴다. 모션 구현과 실행 예제는 재연결하지 않는다.
- 활성 컴포넌트 등록 수와 실제 제품 연결 수는 반드시 일치해야 한다. 가이드 내부의 문서 도구는 `app/design-rules/_documentation/`에 두고 정확한 소스·export를 별도로 감사한다. 제품 미연결 등록, 누락된 도구, 문서 도구의 제품 연결은 검사 실패다.
- 버튼과 레이블은 내용에 맞추고 목록은 남는 너비를 채운다. 고정 크기는 아이콘·좌석 등 공간 관계가 필요한 곳에만 사용한다.
- 테두리는 안쪽으로만 그린다. 공통 컨트롤·표면은 1px inset stroke를 사용하고, 남아 있는 네이티브 경계도 border-box 안에 둔다. 키보드 초점선은 음수 offset으로 안쪽에 표시한다. 일반 상태에 검정·본문색의 진한 스트로크를 사용하지 않는다.
- 기본 컨트롤 12px·flow 14px·패널 20px·compact 16px·dialog 28px 곡률 토큰을 공유한다. 탐색 링크 묶음은 SystemControlGroup의 반응형 비율로 너비를 분배하고 페이지가 링크별 고정 폭을 지정하지 않는다.
- 반복되는 체험·비공식 고지는 제품 화면에 추가하지 않는다. 프로젝트의 성격 안내는 버전 선택 진입점에서 관리한다. 저장·취소·인증 결과는 실제 처리한 내용대로 표현한다.
- 미니룸은 TSX에 직접 구성한 장면을 유지한다. 무작위 방 생성이나 실행 시 외부 생성 서비스로 대체하지 않는다.
- 보존된 구버전 소스·동결 스냅샷은 실제 v5 제품 변경에 필요하지 않으면 그대로 둔다.

루트 AGENTS.md의 TypeScript·커밋 메시지·전체 빌드 산출물 보존 규칙도 따른다.
