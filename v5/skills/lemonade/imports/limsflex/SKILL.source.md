# limsflex — 림스플렉스

`limstandards`에서 파생한 웹 UI 구현 스킬이다. 디자인 표현은 자유롭게 하고, 코드 형식과 웹표준은 엄격하게 지킨다. 로그인·계정 화면 외에도 랜딩 페이지, 대시보드, 콘텐츠 화면 등 웹 UI 전반에 사용한다.

## 디자인과 구현의 기준

- 색상, 서체, 밀도, 여백, 모양, 크기, 일러스트, 효과, 모션, 레이아웃은 사용자 요구와 디자인에 맞게 선택한다. 미니멀하거나 플레인한 디자인을 기본값으로 강제하지 않는다.
- `limstandards`의 브랜드별 색상·폰트·모바일 폭·컴포넌트 치수·화면 구성은 이 스킬의 요구사항이 아니다. 부모 스킬 전체를 불러와 시각적 제한을 다시 적용하지 않는다.
- 사용자 명시 지시가 우선이다. 그다음 현재 프로젝트의 계약과 이 스킬의 코드 규칙을 함께 적용한다. 외부 라이브러리의 클래스나 기존 공용 API는 유지하고, 새로 작성하는 클래스에는 `-` 규칙을 적용한다.
- 독립 HTML 화면의 기본 산출물은 완전한 HTML 문서와 `<head>` 안의 페이지용 `<style>`이다. 기존 앱에서는 요청받은 파일·컴포넌트 구조를 유지한다. 사용자가 HTML만 또는 별도 CSS를 요청하면 그 형식을 따른다.
- 필요한 상호작용은 표준 JavaScript와 프로젝트의 기존 방식으로 구현할 수 있다. 정적 화면에 불필요한 동작이나 프레임워크를 추가하거나 요청 없이 기술스택을 바꾸지 않는다.

## 작업할 때 읽을 자료

코드를 작성하거나 검토하기 전에 [코드·웹표준 계약](references/code-contract.md)을 읽는다. 기본 CSS를 선택·수정할 때는 [제공 기본 CSS](assets/default.css)와 실제 프로젝트의 기본 CSS를 확인한다. 완료 전에는 요청에 해당하는 [수용 시나리오](tests/acceptance.md)를 확인한다.

## Reminder: 기본 CSS를 반드시 준비한다

HTML/CSS UI 구현에는 기본 CSS가 포함되어야 한다. 링크를 적는 것만으로 끝내지 말고, 실제 파일이 존재하고 페이지에 적용되는지 확인한다.

1. 프로젝트에 적합한 `default.css` 또는 동등한 기본 스타일이 있으면 먼저 내용을 확인하고 재사용한다. 기존 기본 CSS를 사용한다는 이유로 이미 제공된 reset을 페이지 CSS에 중복 작성하지 않는다.
2. 적합한 기본 CSS가 없으면 이 스킬의 `assets/default.css`를 프로젝트의 `css/default.css` 등 실제 사용할 경로에 복사한다. 스킬 디렉터리 자체를 페이지의 런타임 경로로 참조하지 않는다.
3. 제공 CSS는 출발점이다. **필요하면 얼마든지 직접 수정하거나 프로젝트에 맞는 자신만의 `default.css`를 새로 만든다.** 기존 파일을 교체할 때는 공유 페이지에 미치는 영향을 확인하고 작업 범위를 지킨다.
4. 직접 만든 기본 CSS도 box sizing, 기본 여백, 미디어 크기, 폼 서체 상속, 키보드 포커스, 숨김 처리 등 프로젝트에 필요한 기반을 갖춘다. 네이티브 컨트롤과 접근성을 파괴하는 reset을 넣지 않는다.
5. 기본 CSS는 페이지 스타일보다 먼저 로드한다. 실제 HTML 위치를 기준으로 경로를 계산한다. 한 파일로 전달해야 하면 기본 CSS를 `<style>` 앞부분에 포함하고 페이지 CSS와 구분한다. 기존 앱의 공용 기본 스타일은 기존 진입점에서 로드한다.

폰트·색상·레이아웃·컴포넌트 스킨은 기본 CSS에 강제하지 않는다. 링크 없는 폰트, 존재하지 않는 에셋·favicon 경로를 만들어 넣지 않는다.

## 반드시 지킬 코드 형식

- HTML 중첩은 단계마다 **공백 4칸**이다. 탭, 2칸 들여쓰기, 전달용 코드의 압축 형식을 사용하지 않는다.
- CSS 최상위 선택자는 첫 칸에서 시작한다. 선언은 4칸, `@media` 등 안의 선택자는 4칸, 그 선언은 8칸이다. `<style>` 안에서도 같은 형식을 적용한다.
- CSS 선언은 한 줄에 하나, 콜론 뒤 공백 하나, 끝에 세미콜론을 쓴다. 여는 중괄호는 선택자 줄에, 닫는 중괄호는 해당 선택자와 같은 깊이에 둔다.
- 직접 만드는 클래스는 소문자 **kebab-case**다. 예: `hero-section`, `product-card`, `is-active`, `sr-only`. BEM·camelCase·밑줄로 새 클래스 체계를 만들지 않는다. 단일 단어인 `title` 등은 허용한다.
- 의미 있는 그룹 사이에 빈 줄 하나를 사용한다. 긴 HTML 속성은 한 줄에 하나씩 쓰고 닫는 `>`를 시작 태그와 정렬한다.
- CSS `opacity`와 색상의 알파값은 `20%`처럼 퍼센트로 쓴다. CSS 변수명·ID·외부 클래스에는 클래스명 규칙을 일괄 적용하지 않는다.

## Reminder: 관련 콘텐츠를 묶고 URL fragment용 고유 ID를 부여한다

관련 콘텐츠를 의미에 맞는 `section`·`article`·`nav`·목록·`fieldset` 등으로 묶고, 의미 있는 그룹 컨테이너마다 목적을 나타내는 고유하고 안정적인 kebab-case `id`를 부여한다. 제목 있는 주제에는 `section`을 쓰고 시각적 래퍼는 필요에 따라 `div`를 유지한다.

그룹으로 이동하는 링크는 실제 `<a href="#features">`처럼 작성해 URL에 `#features`가 나타나게 한다. `id`만 추가하면 현재 URL이 저절로 바뀌지는 않는다. `page.html#features` 직접 진입·새로고침·뒤로/앞으로 이동과 고정 헤더 아래 대상 노출을 확인한다. 세부 예시는 코드 계약의 관련 콘텐츠 그룹 규칙을 따른다.

## 웹표준과 검증을 강화한다

시맨틱 HTML, 올바른 콘텐츠 중첩, 네이티브 컨트롤, 명시적 레이블, 키보드 조작과 보이는 포커스를 필수로 확인한다. ARIA는 네이티브 HTML로 표현하지 못하는 정보를 보완한다.

구조는 일반 문서 흐름과 Flexbox를 우선하고, 2차원 배치는 Grid를 사용할 수 있다. 장식·겹침 표현은 디자인에 맞게 사용하되 주요 콘텐츠를 고정 좌표로 붙여 반응형과 읽기 순서를 깨뜨리지 않는다. 세부 조건과 예시는 코드 계약을 따른다.

완료 전에는 들여쓰기·클래스명·스타일 경로·DOM 의미·선택자 범위를 확인하고, 브라우저에서 요청된 표현과 주요 동작을 검증한다. 좁은 화면, 긴 콘텐츠, 확대, 키보드 조작, 사용자 모션 설정에서 콘텐츠가 손실되지 않는지 확인한다. 형식이나 웹표준 문제를 발견하면 전달 전에 수정한다. 브라우저 검증을 실행할 수 없었다면 실행하지 못한 항목을 짧게 명시하고 검증 완료라고 말하지 않는다.
