# lemonade 공통 판단 기준

공식 표기는 **lemonade / 레모네이드**다. 결과물은 실제 고객 브랜드를 따른다.
사용자 요구 → 기존 콘텐츠·브랜드·동작 → 접근성과 과업 → 관찰한 레퍼런스 → 스타일 프리셋 순으로 판단한다.
이 문서는 과업을 확장하지 않는다. 작은 수정은 주변 시스템을 따른다.
다른 스킬의 절대 금지·고정 수치·필수 레이아웃은 명시적으로 선택한 스타일의 프리셋이다.
실제 기능·명시적 디자인·접근성과 충돌하면 보존해야 할 항목과 선택 이유를 기록한다.

## 레퍼런스가 바꿔야 하는 결정

- 전체를 본 뒤 중요한 영역을 원본 픽셀로 확대한다. 글자·정렬이 안 읽히면 더 나눈다.
- 실제 과업, 필수 데이터, 증거, 밀도, 이미지 형태, 주/보조 비율, 행동을 추출한다.
- 적용할 경우와 적용하지 않을 경우를 함께 기록한다. 색상과 장식만 가져오지 않는다.
- 필요한 역할이 설명될 때까지 관련 사례와 대조 사례를 비교한다. 모든 파일을 무조건 읽지 않는다.
- 정적 이미지에서 보인 컨트롤의 동작·모바일·접근성은 별도 확인 전까지 미확인이다.

| 구성 | 적합한 목적 | 확인할 것 |
| --- | --- | --- |
| 동일 카드·그리드 | 공연·상품·기사·성과 비교 | 이름·날짜·가격·상태의 정렬과 정보 보존 |
| 기능 아이콘 | 예매·달력·위치·지원 바로가기 | 텍스트 이름·목적지·포커스·터치 영역 |
| 얇은 구분선 | 표·일정·목록·푸터 구조 | 정보 단위 구분과 가독성 |
| 라벨·칩 | 분류·예매 상태·날짜 | 읽기, 색상 외 상태 설명 |
| 다열 푸터 | 연락·지원·정책·탐색 | 실제 링크와 모바일 읽는 순서 |
| 브랜드 색·세리프·그림자 | 정체성·계층·떠 있는 요소 | 문맥, 대비, 초점, 조작 |

과업이 달라지면 밀도와 위계를 다시 설계한다. 장식을 줄였다고 빈 화면을 좋은 디자인으로 간주하지 않는다.
실재하는 콘텐츠와 검증 가능한 증거가 필요하다. 고객·후기·수치를 만들지 않고 예시 데이터는 표시한다.

## 한글과 검증

긴 공연명·기사명을 영어 단어 수나 두 줄 규칙 때문에 훼손하지 않는다. 실제 폰트·문장·폭으로 확인한다.
본문 16–18px, 한글 행간 약 1.5–1.7, 터치 영역 약 44px은 출발값이며 캡처에서 복원한 CSS 수치가 아니다.
`word-break: keep-all`을 써도 긴 URL/코드에는 별도 넘침 처리가 필요하다.
모바일에서 열 수·메타데이터 순서·이미지 크롭·주 행동을 다시 설계한다. 달력에는 읽기 쉬운 일정 목록을 고려한다.
넘침·깨진 자산·글자 겹침/잘림·대비 오류·가짜 완료 상태·접근 불가능한 조작은 수정한다.
스타일 경고는 기능과 증거로 판단한다. 자동 통과가 시각 품질 검증은 아니다.
코드 구현과 검증에는 [implementation-review.md](implementation-review.md)를 필요한 범위만 읽는다.
정적 화면·열린 UI·오류·성공·반응형 전환을 구분하고, 검사 전 정의한 예상 결과로 실제 과업을 확인한다.
보지 않은 페이지·모바일·애니메이션을 보았다고 하지 않는다. 레퍼런스 저작물 재사용 권리는 별도다.

섹션은 [wireframe.md](wireframe.md), 새 근거 반영은 [learning-loop.md](learning-loop.md)를 읽는다.
